# 天气看板「生活提醒」功能：竞品调研与可落地方案

> 调研对象：墨迹天气、彩云天气、中国天气网、小米/华为天气、Apple Weather、Carrot Weather、Windy、和风天气 API、华风爱科 API、开源规则引擎

> 撰写日期：2026-10（数据以调研当日公开资料为准）

## 0. 一句话结论

**生活指数这件事，中国气象局已经有国标/行标了** —— 穿衣用 `QX/T 385—2017`（7 级，附完整计算公式），紫外线用 `GB/T 36744—2018`（5 级，附录 B 有完整分档 + 防护措施）。**不要自己拍脑袋定阈值**，直接落地这两份标准，你就比 90% 的同类产品更权威。剩下的指数（带伞、运动、洗车）用「中国天气网/和风天气的实际文案 + Open-Meteo 可得字段」拼装即可。

### 1.3 哪些是「刚需」（普遍都有）

跨 5 个以上产品都出现的，可以认定是刚需：

1. **穿衣指数** —— 全部中国产品都有，且中国天气网明确说它是「被引用最广泛的气象指数产品」
2. **紫外线 / 防晒** —— 全部中国产品都有 + 国标 GB/T 36744
3. **洗车指数** —— 全部中国产品都有
4. **运动指数** —— 和风/彩云/华风/墨迹都有
5. **感冒 / 疾病指数** —— 中国产品几乎全有（这是中国特色，国外产品没有）
6. **舒适度指数** —— 中国产品几乎全有
7. **降水/带伞提醒** —— 中外**全部**产品都有（这是唯一全球共识项）

### 1.4 哪些是「少数才有」（可删）

- 啤酒指数、约会指数、心情指数、放风筝指数、划船指数、夜生活指数 —— **只有彩云/华风的 28 项大而全列表里有**。中国天气网科普明确说这类是「提供给特殊专业用户的」，例如划船指数是公园管理部门关注的、霉变指数是食品仓储部门关注的。**个人看板不需要**。

## 2. 核心项的触发阈值表（可直接写进代码）

### 2.1 穿衣指数 —— 国标行标原文 ⭐

**来源：QX/T 385—2017《穿衣气象指数》，中国气象局 2017-10-30 发布，2018-03-01 实施**
标准 PDF：https://www.cma.gov.cn/zfxxgk/gknr/flfgbz/bz/202209/P020220921693134561491.pdf

**关键设计思想**：该标准**不是按气温分档，而是按「服装厚薄度 H」分档**，H 由气温、湿度、风速综合算出。标准编制组用 2013–2014 年全国 2400 个县级城市逐日预报数据做了验算。标准原文明确批评了网上流传的「穿衣公式」（26℃ 减去气温）不科学。

#### 表 1（标准原文抄录）：穿衣气象指数及对应的服务用语

| 穿衣气象指数 | 服装厚薄度 H | 服务用语（官方文案，可直接用） |
|---|---|---|
| 1 | H > 25.0 | 适宜穿着厚羽绒服、戴手套等严冬装 |
| 2 | 15.0 < H ≤ 25.0 | 适宜穿着棉衣、皮衣，内着厚毛衣等冬装 |
| 3 | 8.0 < H ≤ 15.0 | 适宜穿着夹克衫外套等初冬装 |
| 4 | 4.0 < H ≤ 8.0 | 适宜穿着套装、夹克衫等早春晚秋装 |
| 5 | 1.5 < H ≤ 4.0 | 适宜穿着棉衫、长袖 T 恤、牛仔服等春秋装 |
| 6 | −1.2 < H ≤ 1.5 | 适宜穿着轻薄的衬衣和长裙等夏装 |
| 7 | H ≤ −1.2 | 适宜穿着短袖 T 恤、短裙、短裤等盛夏装 |

#### 服装厚薄度 H 的完整算法（标准第 4 章）

```
第一步：H' = 分段函数（Tm − T 为温差，v 为风速 m/s，rRH 为相对湿度 %）
        T ≤ 5 且 rRH ≥ 60        →  [1 + 0.4×(rRH − 60)] × 0.61×(Tm − T) / (1 − 0.01165×v²)
        T ≤ 5 且 rRH < 60        →  0.61×(Tm − T) / (1 − 0.01165×v²)
        5 < T ≤ 18 且 rRH ≥ 60   →  [1 + 0.4×(rRH − 60)] × 0.61×(Tm − T) / (1 − 0.01165×v²)
        T > 26 且 rRH ≥ 60       →  [1 − 0.4×(rRH − 60)] × 0.61×(Tm − T) / (1 − 0.01165×v^1.5)
        18 < T ≤ 26 且 rRH ≥ 60  →  0.61×(Tm − T) / (1 − 0.01165×v^1.5)
        或 T > 5 且 rRH < 60     →  0.61×(Tm − T) / (1 − 0.01165×v^1.5)

第二步：H = H' + ε_weather + ε_season
        ε_weather：晴或多云天气 = −0.5，其他天气 = 0
        ε_season ：9–10 月 = −0.5，3–4 月 = +0.5，其他月 = 0
```

参数说明（标准原文）：
- `Tm` —— 裸露皮肤所适应的空气温度值，**取当地最高温度历史样本的第 90 百分位值**（℃）
- `T` —— 某时段**最高气温**（℃）
- `v` —— 某时段**平均风速**（m/s）
- `rRH` —— 某时段**平均相对湿度**（%）

> ⚠️ **落地建议**：`Tm` 需要历史气候数据，Open-Meteo 单次请求拿不到。**实用降级方案：用 `apparentTemperature`（体感温度）直接映射档次**，体感温度已经把湿度、风速、辐射算进去了，比裸气温更接近 H 的物理含义。下面的阈值是**依据 QX/T 385 表 1 的 H 档位 + 体感温度语义反推的工程近似值**，已在表中标注来源性质。

#### 工程近似映射表（写入代码用）

| 档 | 体感温度区间（℃） | 文案（国标原文） | 短文案（看板用） | emoji |
|---|---|---|---|---|
| 严寒 | ≤ −10 | 适宜穿着厚羽绒服、戴手套等严冬装 | 厚羽绒服 + 手套 | 🧥 |
| 冬装 | −10 ~ 5 | 适宜穿着棉衣、皮衣，内着厚毛衣等冬装 | 棉衣 / 皮衣 | 🧥 |

### 2.2 紫外线指数 —— 国标原文 ⭐

**来源：GB/T 36744—2018《紫外线指数预报方法》附录 B（资料性附录）**
标准 PDF：https://www.cma.gov.cn/zfxxgk/gknr/flfgbz/bz/202209/P020220921700668017734.pdf

#### 表 B.1（标准原文抄录）：紫外线指数等级划分

| 等级 | 紫外线指数（UVI） | 紫外线照射强度 | 防护措施（官方文案，可直接用） |
|---|---|---|---|
| 一级 | 0 ~ 2 | 最弱 | 不需要采取防护措施 |
| 二级 | 3 ~ 4 | 弱 | 可以适当采取一些防护措施，如：涂擦防护霜等 |
| 三级 | 5 ~ 6 | 中等 | 外出时戴好遮阳帽、太阳镜和太阳伞等，涂擦 SPF 指数大于 15 的防晒霜 |
| 四级 | 7 ~ 9 | 强 | 除上述防护措施外，上午 10 点至下午 4 点避免外出，或尽可能在遮荫处 |
| 五级 | ≥ 10 | 很强 | 尽可能不在室外活动，必须外出时，需采取各种有效的防护措施 |

> **UVI 计算公式（标准第 3.1 节）**：`I_UV ≈ (Q_uv × C_er) / ΔI`，其中 `C_er = 0.01`（等效红斑订正因子），`ΔI = 0.025 W/m²`。
> Open-Meteo 不直接提供 UVI 时，可用 `shortwave_radiation` 近似，或用天气代码 + 日期做降级估算。**建议：Open-Meteo 支持 `uv_index` 字段，直接加上即可。**

**国际口径对照（WHO/UNEP/WMO/ICNIRP 联合制定）**，与国标略有差异，用于英文/国际化场景：

| UVI | 分级 | 颜色 |
|---|---|---|
| 0–2 | Low | 绿 |
| 3–5 | Moderate | 黄 |
| 6–7 | High | 橙 |
| 8–10 | Very High | 红 |
| 11+ | Extreme | 紫 |

来源：[ICNIRP UV Index](https://www.icnirp.org/en/applications/uv-index/uv-index.html)、[华风爱科 紫外线强度指数](https://platform.weathercn.com/doc/resources/uv-index.html)

> ⚠️ 注意差异：国标三级 = UVI 5–6，而国际 Moderate = 3–5。**中国用户场景优先用国标 GB/T 36744。**

### 2.3 带伞 / 降水提醒

**没有查到国标，但有两个可用的官方分档：**

**(a) 华风爱科「雨伞指数」—— 4 级，文案极简**（来源：[华风爱科 指数列表](https://platform.weathercn.com/doc/resources/indices.html)）

| 级别 | 含义 |
|---|---|
| 1 | 不带伞 |
| 2 | 带伞 |
| 3 | 带伞 |
| 4 | 带伞 |

> 这个设计很好：**只有「不带伞」和「带伞」两种输出**，级别 2/3/4 的差异只体现在详情里。**建议直接抄。**

**(b) 工程可执行规则**（基于 Open-Meteo 可得字段，作者综合推理）：

```
未来 12 小时 hourly[] 中：
  max(precipitationProbability) ≥ 60%   → 必带伞（"今天有雨，出门带伞"）
  40% ≤ max < 60%                        → 建议带伞（"可能有雨，带把伞更稳妥"）
  max < 40% 且 current.precipitation > 0 → 正在下雨（"正在下雨，注意防雨"）
  max < 40%                              → 不带伞（此条可不下发，见第 5 节）
另外：若 daily[0].tempMin ≤ 0 且降水概率 ≥ 40% → 雨夹雪/结冰警告（升级为高优先级）
```

> 时间窗选择依据：中国天气网「下班天气」会单独播报当日傍晚天气（见 [黑龙江 生活气象指数预报](http://hlj.weather.com.cn/tqyw/09/2773114_m.shtml)），说明**按用户出行时段播报比按全天平均更有用**。

### 2.4 运动指数

**和风天气官方 3 级**（来源：[和风天气 指数类型](https://dev.qweather.com/docs/api/indices/indices-type/)）：(1) 适宜 (2) 较适宜 (3) 较不宜

**华风爱科官方 3 级**（来源：[华风爱科 指数列表](https://platform.weathercn.com/doc/resources/indices.html)）：(1) 适宜 (2) 较适宜 (3) 较不宜

**和风天气真实返回文案样例**（来源：[和风天气 天气指数预报](https://dev.qweather.com/docs/api/indices/indices-forecast/)）：

```json
{
  "name": "运动指数",
  "level": "3",
  "category": "较不宜",
  "text": "天气较好，但考虑天气寒冷，风力较强，推荐您进行室内运动，若户外运动请注意保暖并做好准备活动。"
}
```

**工程可执行规则**（作者综合推理，基于体感温度 + 降水概率 + 风速）：

| 条件 | 等级 | 文案 |
|---|---|---|
| 体感 15–25℃ 且 降水概率 < 30% 且 风速 < 20 km/h | 适宜 | 天气不错，适合户外运动 |
| 体感 5–15℃ 或 25–30℃ 或 风速 20–35 km/h | 较适宜 | 可以运动，注意热身和补水 |
| 体感 < 5℃ 或 > 30℃ 或 降水概率 ≥ 60% 或 风速 ≥ 35 km/h | 较不宜 | 建议改为室内运动 |

### 2.5 洗车指数

**分档（和风/彩云/华风三家一致）**：(1) 适宜 (2) 较适宜 (3) 较不宜 (4) 不宜

**核心判定逻辑 —— 中国天气网官方说明**（来源：[科普：生活气象指数](http://qxkp.net/qxbk/qxzs/202504/t20250429_7036000.html)，北京市气象服务中心公众服务首席张爱英介绍）：

> 「该指数一共分为 **5 个等级**，主要考虑的气象因素包括**降水、降雪、大风、沙尘**等。如果**未来四天都没有**上述天气情况出现，则指数会表达为**非常适宜**洗车；若**未来三天不出现**，则对应的是**适宜**；以此类推，到**第二天会出现**降水、降雪或沙尘时，描述则为**不太适宜**洗车。」

**工程可执行规则**：

```
lookahead = daily[0..3]  （未来 4 天）
若 任一 day.precipitationProbability ≥ 50% 或 weatherCode ∈ {雪, 沙尘}：
    → 不宜洗车
若 仅 daily[1..3] 有降水信号（daily[0] 干净）：
    → 较不宜洗车
若 daily[0..2] 全部干净（未来 3 天无雨雪沙尘）：
    → 适宜洗车
若 daily[0..3] 全部干净（未来 4 天无雨雪沙尘）：
    → 非常适宜洗车
风速修正：当前风速 ≥ 40 km/h 时降一级（"风大易扬尘"）
```

> 💡 这条规则的精华是**「向后看几天」**，而不是只看今天。因为今天洗了明天下雨等于白洗。**这是「贴切生活」的关键。**

## 3. 展示位置与形式建议

### 3.1 竞品实际情况

| 产品 | 位置 | 形式 |
|---|---|---|
| **中国天气网（网页）** | 独立「生活指数」页面（如 `/life/`、各地 `*_shts_more.htm`），**每个指数一张图标 + 一段文字**，垂直列表 | 图标 + 「XX指数：N级，正文…」 |
| **和风天气（网页 fxLink）** | 独立页面 `qweather.com/indices/{city}-{id}.html` | 卡片列表 |
| **Apple Weather** | **不做独立指数区**。通知在系统层；App 内在主界面顶部有一条**高亮提示条**（如「未来一小时有雨」），并且有「天气状况」通知 | 单条横幅 |
| **Carrot Weather** | 通知轰炸（可自定义阈值），App 内为**数据点网格** | 用户自选阈值 |
| **墨迹天气** | 首页有「生活指数」卡片区，点击进二级页 | 图标宫格 |
| **彩云天气** | 首页卡片区 | 图标宫格 |

### 3.2 对 weather-dashboard 的建议：**三处投放，分工明确**

你现有的布局是：主天气卡 → 4 个指标卡 → 2 个图表 → 7 天预报，全部是 `rounded-2xl border border-white/10 bg-white/5 p-5 backdrop-blur-xl` 的玻璃卡。

**建议方案（推荐）：**

```
┌─────────────────────────────────────┐
│  [A] 顶部横幅：1 条「今日头条提醒」   │  ← 主天气卡正上方
├─────────────────────────────────────┤
│  主天气卡                             │
├─────────────────────────────────────┤
│  4 个指标卡                           │
├─────────────────────────────────────┤
│  [B] 生活提醒卡片区（图标 + 短句网格）│  ← 指标卡下方，图表上方
│      ┌────┬────┬────┐                │
│      │ 👕 │ ☂️ │ 🏃 │  ...           │
│      └────┴────┴────┘                │
├─────────────────────────────────────┤
│  2 个图表                             │
├─────────────────────────────────────┤
│  7 天预报                             │
├─────────────────────────────────────┤
│  [C] 折叠区：「全部生活指数」可展开    │  ← 页尾
└─────────────────────────────────────┘
```

**理由：**

1. **顶部横幅（A）解决「需要一直有类似提示」** —— 用户原话第 2 条。这个位置**任何时候都必须有内容**，哪怕天气完美也要有一条（如「今天天气不错，适合外出」）。Apple Weather 就是这么做的，它的提示条常驻主界面顶部。
2. **生活提醒卡片区（B）是主战场** —— 图标 + 短句，2×3 或 3×2 网格，与现有 4 指标卡视觉语言一致（同样 `bg-white/5 backdrop-blur-xl`），不破坏深色玻璃拟态风格。
3. **折叠区（C）满足「越贴切生活越好」但避免信息过载** —— 20+ 项指数一次全铺会变成「什么都说了等于什么都没说」（见第 6 节反面案例）。中国天气网那种一个指数一段长文的列表页，**在笔记本/桌面看板上非常低效**。

**交互形式：**

- 卡片默认**只显示图标 + 4–8 字短句**（如「☂️ 带伞出门」）
- `hover` 或点击展开显示**国标原文的完整建议**（如「外出时戴好遮阳帽、太阳镜和太阳伞等，涂擦 SPF 指数大于 15 的防晒霜」）
- 用 **`<details>` / 受控 state** 做展开，**不要用弹窗**（看板场景弹窗打断感强）
- **必须用 `title` 属性的替代品**：图标 + 文字已经足够，不要只放图标

**关于「一直有提示」的实现细节：**

- 顶部横幅的候选池按优先级取第一条**始终非空**的（见第 5 节，最后一条兜底是「天气平稳」）
- 若数据加载失败，横幅显示之前的占位（你已有 `error.tsx` 和 `dashboard-skeleton.tsx`），**不要留空白**

## 4. 文案模板示例（中文，符合中国用户习惯）

### 4.1 风格分析（基于真实语料）

从抓到的**真实文案**看规律：

| 来源 | 真实文案 | 风格 |
|---|---|---|
| 中国天气网（黑龙江） | 「多云转晴，气温稍低，风力不大，参考着装为单层薄衫裤、薄型棉衫、长裤、长袖Ｔ恤等。」 | 陈述式 + 前置天气因由 |
| 中国天气网（黑龙江） | 「未来三天多云转晴，适宜洗车。」 | 短陈述式 |
| 中国天气网（黑龙江） | 「多云转晴，气温稍低，风力不大，是感冒等呼吸系统疾病的高发期，注意预防。」 | 陈述 + 末尾命令 |
| 哈尔滨气象（微博） | 「10 日小雨转多云，气温下降，风力稍大，参考着装为套装、夹衣、风衣、夹克衫、西服套装。」 | 日期 + 天气因由 + 建议 |
| 和风天气 API | 「天气较好，但考虑天气寒冷，风力较强，推荐您进行室内运动，若户外运动请注意保暖并做好准备活动。」 | **「推荐您…」敬语 + 条件说明** |
| 和风天气 API | 「较不宜洗车，未来一天无雨，风力较大，如果执意擦洗汽车，要做好蒙上污垢的心理准备。」 | **幽默口语化**（罕见） |
| GB/T 36744 国标 | 「尽可能不在室外活动，必须外出时，需采取各种有效的防护措施」 | 命令式（安全类用命令式） |
| Carrot Weather（英文） | UV 达危险值 → 提示涂防晒；温度跌破冰点 → 提示把植物搬进屋 | **「阈值触发即时通知」** |

**结论 —— 混合策略：**

- **安全/健康类 → 命令式**（「必须」「避免」「注意」）。因为后果严重，需要行动指令。国标 GB/T 36744 五级用的就是「尽可能不在室外活动」。
- **生活建议类 → 陈述式 + 轻命令**。中国天气网的「参考着装为……」比「你应该穿……」更舒服，因为不冒犯用户判断力。
- **长度**：短句 **4–10 字**（卡片位），完整句 **20–45 字**（展开位）。
- **emoji**：中国天气网/和风/彩云的**官方文案完全不用 emoji**。但你的看板是深色玻璃拟态年轻风格，**建议卡片位用 1 个 emoji 做视觉锚点**（与现有 `weather-icon.tsx` 的图标体系协调），完整句不用。**不要在一句里塞多个 emoji。**

## 5. 优先级与数量 + 推荐方案

### 5.1 竞品的数量策略

| 产品 | 一次显示几条 |
|---|---|
| Apple Weather | **1 条**横幅（最高优先级） + 可选的独立通知 |
| Carrot Weather | 用户自定义，**默认克制**，按阈值即时触发 |
| 中国天气网 | **全显示**（列表页，10+ 条，按固定顺序） |
| 墨迹/彩云 | **图标宫格全显示**（通常 6–9 个） |

**结论：做看板，学 Apple（横幅 1 条）+ 墨迹（宫格精简），不要学中国天气网的列表页。**

### 5.2 排序算法建议

给每条提醒一个 `score`，降序取前 N：

```
score = 严重度权重 × 时效系数 × 确定性系数

严重度权重（0–100）：
  安全类（结冰、雷暴、大风、高温≥37℃、严寒≤−10℃）  100
  健康类（紫外线≥7、感冒易发、空气差）                80
  强生活相关（必带伞、温差≥10℃）                      60
  一般生活类（穿衣、运动、洗车）                       40
  氛围类（晾晒、日出日落、空气好）                     20

时效系数：
  影响未来 3 小时内    ×1.5
  影响今天            ×1.2
  影响未来 2–7 天      ×1.0

确定性系数：
  当前实况（已在发生）  ×1.3
  概率 ≥ 70%           ×1.1
  概率 40–70%          ×0.9
  潜势/趋势类          ×0.8
```

**同分时的兜底排序**：安全 > 健康 > 出行 > 穿搭 > 生活起居。

### 5.3 ⭐ 如果只能做 5 项，选哪 5 项？

**推荐 5 项（按优先级）：**

| # | 指数 | 为什么必须做 |
|---|---|---|
| **1** | **带伞 / 降水提醒** | **唯一的中外全部产品共识项**（Apple、Carrot、Windy、墨迹、彩云、中国天气网全都有）。它是天气 App 最高频、最高价值的单点提醒。而且 Open-Meteo 的 `precipitationProbability` + `precipitation` 两个字段足以做出**带时段**的高质量提醒。 |
| **2** | **穿衣指数** | **中国气象局有正式行标 QX/T 385—2017**，7 级分档 + 官方服务用语 + 完整算法，**照抄即可，零争议**。且中国天气网明确说它是「被引用最广泛的气象指数产品」。这是「贴切生活」最直接的答案。 |
| **3** | **紫外线 / 防晒** | **有国标 GB/T 36744—2018**，5 级分档 + 官方防护措施文案。用户对防晒有强需求（尤其女性用户），且 UVI 是**离散数值**容易做出精准提醒。 |
| **4** | **运动指数** | 和风/彩云/华风/墨迹**四家都有**，3 级分档简单。它把「体感温度 + 降水 + 风速」三个字段串起来，是**最能体现「智能」感**的一项（用户会觉得「它真的懂今天适不适合跑步」）。 |
| **5** | **温差 / 感冒提醒** | **中国特色刚需**，中国产品几乎全有，国外产品全没有。用 `daily[0].tempMax − tempMin` 一个减法就能算，成本极低但**「洋葱式穿衣」类的提醒极贴切中国用户生活**（中国天气网专门为此发过科普，见 [人民日报客户端报道](https://www.hunantoday.cn/news/xhn/202511/30802817.html)）。 |

**为什么砍掉洗车、晾晒、钓鱼、化妆等？**

- **洗车/晾晒**：需要「向后看 3–4 天」，价值真实但**频次低**（一周一次），且与「带伞」的信息高度重合（都是降水驱动）。
- **钓鱼/化妆/美发/啤酒/约会**：中国天气网官方定性这些是「特殊专业用户」或营销向内容，**个人看板做这些会显得凑数**。
- **空气污染扩散**：**Open-Meteo 的当前请求字段里没有 AQI**，做不了。这条是硬约束。

**如果还有预算，第 6 和第 7 项加：洗车 + 晾晒**（复用同一套「未来 N 天无降水」逻辑，代码几乎零增量）。

## 6. 反面案例（做得差的地方 + 原因）

### 6.1 中国天气网列表页：信息密度过低，像公告栏

**现象**：一个指数一段 30–50 字长文，10+ 个指数平铺，无优先级、无折叠。例如 [重庆生活指数页](https://cq.weather.com.cn/qxsj/chongqing_shts_more.htm)：

> 城市火险指数预报:一级，物体难于着火，但防火人员必须坚守岗位，以免发生人为火灾。
> 仓库火险指数预报:二级，较易燃烧，请安全用电，严防短路。
> 饮料指数预报:四级，适宜喝清淡的天然系列饮料。

**为什么差**：
1. **「城市火险」「仓库火险」对普通用户毫无意义** —— 中国天气网自己的科普都说这类是给专业部门的。
2. **「饮料指数：适宜喝清淡的天然系列饮料」是纯废话** —— 它不是一个由天气数据驱动的真实建议。
3. **无优先级**：防火灾的提醒和「喝什么饮料」并排显示，用户无法判断该看哪个。
4. **「物体难于着火，但防火人员必须坚守岗位」** —— 这句话的受众根本不是普通市民。

**教训：** 发布 40 种指数是气象部门的职责（面向各行业），但**产品一次只能给用户 3–5 条**。不要把「数据源有什么」等同于「界面该显示什么」。

### 6.2 中国天气网重庆页的逻辑 bug：用「一级」表达「好事」

> 洗车指数预报:**三级**，**不适宜**洗车……
> 晨练指数预报:**四级**，天气**适宜**晨练。
> 行驶指数预报:一级，天气对道路交通影响不大。

**为什么差**：**等级数字的方向不统一**。洗车是「数字越大越差」，行驶指数是「数字越小越好」，晨练指数「四级」居然表示「适宜」。用户看到一个数字完全无法判断好坏。

中国气象局在制定穿衣标准时正是发现了这个问题 —— 标准起草人王静说：

> 「有的地方分 12 个等级，1 级最冷，12 级最热；有的地方分 5 个等级，1 级最热，5 级最冷。**公众从一个地方到另一个地方，看到这样的穿衣气象指数会很混乱，也没有实际的指导价值。**」
> —— [广东省气象局报道](http://gd.cma.gov.cn/yfsqxj_3345/qxfw_3396/qxkp_3400/fzbd_3401/201808/t20180825_73930.html)

**教训：** **不要给用户看等级数字**。直接给「图标 + 短句 + 颜色」。数字（无论几级）对用户是噪音。你的看板应该输出 **「☂️ 带伞出门」** 而不是 **「雨伞指数：2 级」**。

### 6.3 「穿衣公式」类伪科学：被官方点名批评

网上热传的「26℃ 穿衣公式」（厚羽绒服 = 9℃，薄外套 = 3℃，用 26 减去气温做加法）被中国气象局公共气象服务中心高级工程师王静**明确否定**：

> 「即使是同样的气温，南方和北方给人的感觉完全不一样；就算同一个地方，同样的气温，是否有太阳、是否有风给人的感觉也不一样。因此，更具指导意义的穿衣指数应该**综合考虑气温、湿度、风速**等气象要素。」
> —— [广东省气象局报道](http://gd.cma.gov.cn/yfsqxj_3345/qxfw_3396/qxkp_3400/fzbd_3401/201808/t20180825_73930.html)

**教训：** **不要用「气温单值分档」做穿衣建议**（如「< 5℃ 穿羽绒服」）。至少要用 `apparentTemperature`（体感温度），它已经综合了湿度、风速、辐射。**这是本次调研最重要的技术结论之一。**

### 6.4 墨迹天气类产品的「指数轰炸」

**现象**：国产天气 App 普遍在首页铺 9–16 个指数宫格（穿衣、洗车、紫外线、运动、钓鱼、化妆、美发、感冒、晾晒、旅游、交通、过敏……）。

**为什么差**：
- **每个指数都要占一个视觉槽位**，用户需要逐个扫读才能找到跟自己有关的。
- **大部分指数常年不变**（比如内陆城市的钓鱼指数、非过敏季的过敏指数），形成「狼来了」效应，用户会训练自己**忽略整个区域**。
- 与「一直有类似提示」的需求**方向相反**：铺得越满，用户越不看。

### 6.5 数据准确性是致命伤（连头部产品也会翻车）

**彩云天气用户实测吐槽**（[新浪微博用户原文](https://www.sina.cn/news/detail/5306822417455280.html)）：

> 「今天温度这么低，它非得预报 30 度。已经过去的温度还是它自己预报的温度，只有当前温度是实时温度，然后温度曲线变成了一个井。以前因为准确用的彩云天气，现在还没自带的天气靠谱，卸载！」

**为什么重要**：**这不只是数据 bug，它会摧毁整个「生活提醒」功能的信任基础。** 如果用户发现「建议穿短袖」但外面在下雪，他会永久关闭这个模块。

**对你的开发建议：**
1. **提醒的触发条件要保守**。宁可漏报（少提醒一次），不要误报（提醒错一次）。
2. **概率类建议必须带概率**（「降水概率 75%」而不是「今天有雨」），把不确定性交给用户判断。
3. **绝不用「已经过去的预报」做当前建议** —— 只基于 `current.*` 实况 + `hourly[]` 未来数据。

### 6.6 Windy 的定位错配

Windy 是**专业气象可视化工具**（风场动画），它的「生活提醒」能力很弱，主要服务于帆船、飞行、冲浪等专业用户。**它的取舍是对的**（不做生活指数，专注可视化），但如果照搬 Windy 到生活看板场景，会得到一个「很酷但没用」的产品。

**教训：** 生活提醒是**给普通人的行动建议**，不是气象数据展示。判断标准是：**看完这条提醒，用户会改变今天的一个行为吗？** 如果不会，就不要做。

### 7.1 数据层改造（Open-Meteo）

```ts
current: [

],
hourly: [
  // ...保留现有全部字段
  "apparent_temperature",  // ⭐ 新增：体感温度（穿衣/运动的核心输入）
  "uv_index",              // ⭐ 新增：逐小时紫外线
],

  // ...保留现有全部字段

```

> Open-Meteo 的 `uv_index` 与 WHO/国标口径一致，可直接套用 GB/T 36744 分档。

### 7.2 新增文件结构建议

```
src/lib/
  weather.ts            （改：增加 uv_index / apparent_temperature 字段）
  life-tips.ts          （新：规则引擎，纯函数，无副作用、无持久化）
  life-tips.data.ts     （新：阈值常量表，与逻辑分离，方便调参）
src/components/
  life-tips-banner.tsx  （新：顶部横幅，1 条）
  life-tips-grid.tsx    （新：图标 + 短句网格，可展开）
```

**`life-tips.ts` 的核心签名建议：**

```ts
export type LifeTip = {
  id: string;                                  // "dressing" | "umbrella" | ...
  icon: string;                                // emoji
  title: string;                               // 短句，"带伞出门"
  detail: string;                              // 完整句，国标原文或模板
  severity: "info" | "advice" | "warning";     // 决定卡片配色
  score: number;                               // 排序用（见 5.2）
  source?: string;                             // "QX/T 385—2017" 等，增强可信度
};

export function buildLifeTips(data: WeatherData): LifeTip[];
```

**关键约束（对应用户需求）：**
- ❌ **不做持久化**（用户明确说「不用历史记录」）—— 函数纯计算，不写 localStorage / DB
- ✅ **始终非空**（用户说「需要一直有类似提示」）—— `buildLifeTips` 保证至少返回 1 条兜底项
- ✅ **纯函数** —— 便于单元测试阈值边界（如 12℃ 落在哪一档）

### 7.3 落地顺序

| 阶段 | 内容 | 依据 |
